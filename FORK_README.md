# Tulasi (fork build)

This is a fork of [shringarstudio/Tulasi](https://github.com/shringarstudio/Tulasi) with a proper automated build.

## What's different from upstream

1. **No symlinks.** Upstream uses symlinks for app-name aliases. This breaks in some browsers, file managers, and KDE lookups when packaged as a zip. This build uses real file copies.
2. **Real `index.theme`.** Generated fresh on every build, only declares directories that actually have files in them.
3. **GitHub Actions build.** Push to `main` and a ready-to-install `.zip` shows up as a workflow artifact. Push a `v*` tag and it auto-publishes a GitHub release.
4. **Better fallback chain.** `Inherits=papirus,hicolor,breeze,breeze-dark,Adwaita` — anything Tulasi doesn't have, Papirus or your DE's default picks up.

## How to use this fork

### Option 1: Download a build
1. Go to the [Actions tab](../../actions) → click the latest green run → scroll to "Artifacts" → download `Tulasi-build`
2. Extract the zip
3. Move the `Tulasi` folder to `~/.local/share/icons/`
4. Refresh icon cache:
   ```bash
   gtk-update-icon-cache -f -t ~/.local/share/icons/Tulasi
   ```
5. If on KDE, also:
   ```bash
   rm -f ~/.cache/icon-cache.kcache
   kquitapp6 plasmashell && kstart plasmashell
   ```
6. Select "Tulasi" in GNOME Tweaks or KDE System Settings

### Option 2: Add new icons
1. Drop your SVG files into `cow/`, named `mother-something.svg` (must be valid SVG with `xmlns="http://www.w3.org/2000/svg"` and a `viewBox`)
2. Add the icon name and its aliases to the `MAPS` array in `.github/workflows/build.yml` (or just commit the SVGs without alias entries if the filename is what you want)
3. Push to `main` — workflow runs and produces a new artifact

### Option 3: Cut a release
1. Bump version, commit
2. `git tag v0.3 && git push origin v0.3`
3. Workflow builds, attaches the zip to a GitHub Release automatically

## Local build (optional)

```bash
sudo apt install librsvg2-bin imagemagick
# (or: sudo pacman -S librsvg imagemagick)
bash scale.sh
```

The script is regenerated by the workflow but a local copy is also checked in for convenience.
